# 🔬 분석 모드

지금부터 **분석 모드**다. 여전히 코드는 쓰지 않는다.

## 목표
리서치에서 모은 재료로 **결정을 내리고, 그 근거를 남긴다.** 6개월 뒤의 내가 "왜 이렇게 했더라" 를 여기서 찾게 만든다.

## 절차

0. **단계 선언** — `.claude/hooks/harness.py stage analyze` 를 먼저 실행한다.

1. **입력 로드**
   - `$ARGUMENTS` 가 파일명이면 `docs/01_research/` 에서 읽는다.
   - 비어 있으면 `docs/01_research/` 최근 3개를 보여주고 고르게 한다.
   - 해당 리서치가 없으면 **여기서 멈추고** `/research` 를 먼저 하라고 안내한다.

2. **분석**
   - **문제 분해**: 해결해야 할 하위 문제로 쪼갠다.
   - **옵션 비교**: 최소 2개. 표로 — 구현 비용 / 운영 비용 / 리스크 / 되돌리기 난이도.
   - **결정**: 고른 것과 **버린 것 각각의 이유**. 버린 이유가 더 중요하다.
   - **가정**: 이 결정이 깔고 있는 전제를 명시한다. 전제가 깨지면 결정도 재검토 대상이다.
   - **되돌릴 수 있는 결정인지** 판단한다. 되돌리기 쉬우면 빨리 정하고 넘어간다.

3. **기록** — `docs/02_analysis/YYYY-MM-DD_<slug>.md` (양식: `docs/00_templates/analysis.md`)
   - frontmatter `source_research` 에 입력 노트를 링크한다.

4. **마무리** — 저장 경로 + 결정 요약 3줄 + `/plan <파일명>` 제안.

## 제약
- 코드 작성·파일 수정 **금지**.
- 근거 없는 단정 금지. 모든 결론은 리서치 자료 또는 명시된 가정에 연결돼야 한다.
- 사용자 취향이 갈릴 만한 지점은 혼자 정하지 말고 "A vs B" 로 올려서 물어본다.
