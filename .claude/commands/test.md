# 🧪 테스트 모드

## 목표
구현이 끝난 범위의 **테스트 구멍을 찾아 메운다.** 커버리지 숫자를 올리는 게 목적이 아니라, 깨졌을 때 알아차리게 만드는 게 목적이다.

## 절차

0. **단계 선언** — `.claude/hooks/harness.py stage test` 를 먼저 실행한다.

1. **현황 파악**
   - `CLAUDE.md` 의 테스트 명령을 돌려 현재 상태와 커버리지를 확인한다.
   - `$ARGUMENTS` 가 있으면 그 범위로 좁힌다. 없으면 최근 변경(`git diff`)이 닿은 범위를 대상으로 한다.

2. **구멍 찾기** — 이 순서로 본다.
   - **실패 경로**: 예외, 타임아웃, 빈 값/널, 경계값. 정상 경로만 있는 모듈이 1순위 대상이다.
   - **분기**: if/when/switch 중 한 번도 안 타는 가지.
   - **경계**: off-by-one, 빈 컬렉션, 최대/최소.
   - **동시성·I/O**: 재시도, 재연결, 순서 뒤집힘.

3. **보강**
   - Given/When/Then 구조. 테스트 이름은 **무엇이 보장되는지**를 말해야 한다 (`test1` 금지).
   - 테스트 1개 = 단언 1가지 성질. 한 테스트에 여러 성질을 욱여넣지 않는다.
   - 느린 테스트(컨테이너·네트워크)는 태그로 분리해 기본 실행에서 뺀다.
   - **의미 없는 테스트는 만들지 않는다.** getter 검증은 커버리지만 올리고 아무것도 못 잡는다.

4. **기록** — `docs/06_test/YYYY-MM-DD_<slug>.md` (양식: `docs/00_templates/test.md`)
   - 커버리지 before/after, 추가한 케이스, **의도적으로 테스트하지 않기로 한 것과 그 이유**.

5. **마무리** — 테스트 실행 결과 원문 요약 + 남은 리스크.

## 종료 게이트
`Stop` 훅이 변경분에 대해 검증 명령을 돌린다. 테스트가 빨간 채로는 세션이 끝나지 않는다.
새로 쓴 테스트가 진짜 버그를 잡았다면 **그 버그를 고치는 것까지가 이 단계다.**

## 제약
- 테스트를 통과시키려고 프로덕션 코드를 느슨하게 바꾸지 않는다. 테스트가 잡은 건 대개 진짜 버그다.
- 깨지는 테스트를 `skip` 으로 덮지 않는다. 고치거나, 왜 못 고치는지 기록한다.
