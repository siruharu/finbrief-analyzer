# 🗺️ 플랜 모드

지금부터 **플랜 모드**다. 코드는 아직 쓰지 않는다.

## 목표
분석에서 정한 방향을 **한 번에 하나씩 끝낼 수 있는 작업 단위**로 쪼갠다.

## 절차

0. **단계 선언** — `.claude/hooks/harness.py stage plan` 을 먼저 실행한다.

1. **입력 로드**
   - `$ARGUMENTS` → `docs/02_analysis/`. 없으면 `/analyze` 를 먼저 요구하고 멈춘다.

2. **설계**
   - 건드릴 파일/모듈 목록을 표로. 신규인지 수정인지, 각각의 역할.
   - 필요하면 Mermaid 로 구조도 1장. 말로 되는 건 그림 안 그린다.

3. **작업 쪼개기** — 각 Task 는 다음을 만족한다.
   - **1 Task = 1 커밋 = 리뷰 가능한 크기** (변경 400줄 이내 권장).
   - 각 Task 마다: 목적 / 선행 조건 / 먼저 쓸 테스트 / 완료 정의(DoD) / 검증 방법.
   - Task 하나가 끝난 시점에 **빌드와 테스트가 통과하는 상태**여야 한다. 중간에 깨진 채로 넘어가는 분할은 잘못된 분할이다.
   - 의존 관계를 그래프로 정리한다.

4. **불확실한 것 먼저**
   - 확신 없는 부분은 `검증 필요 (PoC)` 에 모으고, **가장 앞 Task 로 배치한다.** 틀렸을 때 버릴 코드가 가장 적은 시점이다.

5. **기록** — `docs/03_plan/YYYY-MM-DD_<slug>.md` (양식: `docs/00_templates/plan.md`)
   - frontmatter `source_analysis` 링크.

6. **마무리** — Task 개수·예상 규모 요약 + `/task <파일명>` 제안.

## 제약
- 코드 작성·파일 수정 **금지**.
- 예상 시간 뻥튀기 금지. 모르면 "모름" 으로 두고 PoC Task 를 만든다.
- Task 가 10개를 넘으면 플랜을 쪼갤 신호다. 사용자에게 분할을 제안한다.
