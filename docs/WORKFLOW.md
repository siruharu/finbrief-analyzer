# 작업 흐름

모든 새 기능·주제는 **리서치 → 분석 → 플랜 → 태스크 → 구현 → 테스트** 순서로 간다.
각 단계는 슬래시 커맨드이고, 산출물 MD 하나를 남긴다. **이전 단계 산출물 없이 다음 단계로 넘어가지 않는다.**

| 단계 | 커맨드 | 저장 위치 | 코드 수정 |
|---|---|---|---|
| 리서치 | `/research <주제>` | `docs/01_research/` | ❌ |
| 분석 | `/analyze <파일명>` | `docs/02_analysis/` | ❌ |
| 플랜 | `/plan <파일명>` | `docs/03_plan/` | ❌ |
| 태스크 | `/task <파일명>` | `docs/04_tasks/` | ❌ |
| 구현 | `/implement <파일명>` | `docs/05_implementation/` | ✅ |
| 테스트 | `/test [범위]` | `docs/06_test/` | ✅ (테스트 코드) |

```
/research 주제        docs/01_research/2026-09-15_topic.md
        ↓
/analyze 2026-09-15_topic
        ↓             docs/02_analysis/...
/plan 2026-09-15_topic
        ↓             docs/03_plan/...
/task 2026-09-15_topic
        ↓             docs/04_tasks/...   ← 브랜치·이슈는 여기서
/implement 2026-09-15_topic   ← 여기서부터 코드가 바뀐다
        ↓             docs/05_implementation/...
/test
                      docs/06_test/...
```

## 강제되는 것 vs 권고인 것

**단계별 금지 사항은 산문이 아니라 훅으로 강제된다.**

| 장치 | 무엇을 | 어떻게 |
|---|---|---|
| `PreToolUse` 훅 | 리서치·분석·플랜·태스크 단계에서 `docs/` 밖 편집 | **차단** (exit 2) |
| `PostToolUse` 훅 | 방금 고친 파일의 린트/포맷 | **차단 + 즉시 되돌림** |
| `Stop` 훅 | implement/test 에서 검증 명령 실패 | **세션 종료 거부** |
| `task done` | 그 태스크의 `verify` 명령 | **실패하면 완료 처리 거부** |
| 커맨드 `allowed-tools` | 읽기 전용 단계의 도구 집합 | 호출 시점에 제한 |
| MD 에 적힌 나머지 규칙 | 서술·판단 기준 | 권고 (지키는지 확인은 사람이) |

단계는 `.claude/state.json` 에 기록되고 슬래시 커맨드가 바꾼다.
상세는 `.claude/README.md`. 훅이 방해되면 `HARNESS_SKIP=1 claude`.

## 규칙

1. **파일명은 `YYYY-MM-DD_<slug>.md`.** slug 는 영소문자-하이픈. 날짜는 작성 시작일.
2. **단계를 건너뛰지 않는다.** 작은 버그 수정은 `/implement` 만 써도 되지만, 그 경우 구현 노트에 "단계 생략 — 이유" 를 남긴다.
3. **frontmatter 의 `source_*` 로 이전 단계를 `[[링크]]` 한다.** 나중에 "왜 이렇게 했지" 를 역추적하는 유일한 수단이다.
4. **양식은 `docs/00_templates/` 에 있다.** 커맨드가 알아서 읽어간다.
   단, **작업 상태만은 예외다** — 정본은 `docs/04_tasks/<주제>.tasks.json` 이고
   마크다운에 체크박스를 다시 적지 않는다. 두 곳을 손으로 맞추면 반드시 어긋난다.
5. **막혔다 푼 건 반드시 구현 노트에 남긴다.** `blog_candidate: true` 로 표시.

## 왜 이렇게 나눴나

리서치와 분석을 섞으면 처음 본 자료로 결론을 내린다. 플랜과 태스크를 섞으면
"어디부터 만지지" 에서 멈춘다. 구현과 테스트를 섞으면 통과하는 테스트만 쓴다.
단계마다 **금지 사항**을 두는 게 이 흐름의 핵심이다.

그리고 금지 사항은 **적어두는 것만으로는 지켜지지 않는다.** 그래서 훅으로 막는다.
가장 중요한 건 `Stop` 게이트다 — "다 했습니다" 를 사람의 말이 아니라 검증 명령이 판정한다.
