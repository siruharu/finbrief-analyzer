# 🔬 분석: LLM 뉴스 선별·요약 단계

## 결론 (먼저)
- **선택**: 수집이 끝난 뉴스(상한 뒤 ≤80건, 제목+리드)를 **Claude API(Opus 5.5, 구조화 출력)** 에 한 번 보내 **N건을 고르고 건별 한 줄 한국어 요약**을 받는다. 결과는 `collect` 와 `compose` 사이의 새 단계(`summarize`)가 만들고, 작성기는 그것이 있으면 "뉴스" 섹션을 `lines`(요약) + `links`(원문)로 채운다. **없거나 실패하면 지금의 최신순 10건 목록(v0)으로 그대로 간다.** 모델·N·effort 는 PoC 로 정한다.
- **이유 3줄**:
  1. 입력이 제목+100자 리드뿐이라(실측) "흐름 서술"은 날조 위험이 크고, 건별 한 줄은 재료에 맞으며 각 줄이 원문 링크로 검증된다. 저작권 지침도 "제목+첫 한두 줄+링크"는 무방하고 "새 문장"이어야 한다고 적는다.
  2. 뉴스 섹션은 required 가 아니다. LLM 단계가 빠져도 메일은 간다 — 되돌리기가 공짜라 빨리 정하고 PoC 로 검증한다.
  3. 하루 2회라 어느 모델이든 월 $7 아래다. 가장 좋은 결과를 기준선으로 삼고(Opus 5.5) 같은 입력으로 Sonnet·Haiku 를 비교해 내리는 쪽이, 싼 모델로 시작해 품질을 의심하는 쪽보다 결정이 빠르다.

## 결정
### 1. 입력
- **상한 뒤 전체(≤80건)** 를 넣는다. 출처·언어를 가리지 않는다. 더 줄이면 고를 재료가 줄고, 토큰 비용은 어차피 호출당 15K 이하다.
- **DART 공시도 후보에 넣는다**(제목만). 선별 대상이 될 가치가 있다("유상증자 결정" 등). 단, 리드가 없는 항목의 한 줄은 제목을 다시 쓴 수준이어야 하고, 입력에 없는 내용을 더하지 않는다는 규칙을 프롬프트에 둔다.
- **연합 머리말 "(○○=연합뉴스) ○○○ 기자 ="** 은 LLM 입력을 만들 때 벗긴다. 수집 모델은 그대로 둔다(원문 보존, 수집 쪽 변경 없음).
- **영문 기사도 한국어 한 줄로** 쓴다. 브리핑은 한국어다.
- 각 항목에 **번호**를 붙여 보내고, 모델은 **번호로 고른다.** URL·제목을 모델이 다시 쓰게 하지 않는다 → 링크 날조가 구조적으로 불가능하다.

### 2. 제공자·모델
- **Claude API.** 한국어 공식 수치가 있고, 구조화 출력이 GA 이며, 로컬 옵션은 노트북 절전과 사양 미확인이라는 두 미지수를 더한다.
- **`claude-opus-5-5`** 로 시작(사용자 결정). thinking 은 기본(어댑티브), effort 는 기본 `medium` 을 명시적으로 적고 PoC 에서 `low` 와 비교한다. `max_tokens` 는 4,000(출력 추정 2,700 + 여유).
- 타임아웃 **120초**, SDK 재시도 기본 2회. 작업 전체 제한이 30분이고 뉴스 섹션은 선택이라 길게 기다릴 이유가 없다.
- 캐싱·배치는 쓰지 않는다. 시스템 프롬프트+스키마가 512 토큰에 못 미칠 수 있고 호출 간격이 TTL(5분)을 넘는다. 배치는 월 $3 절약에 폴링 코드를 더하는 거래라 지금은 안 한다.

### 3. 출력 계약
- 구조화 출력(`output_config.format` / Python `messages.parse`) 으로 받는다:
  `{ "picks": [ { "index": int, "line": str }, … ] }` — `index` 는 입력 번호, `line` 은 한국어 한 문장(길이 상한은 PoC 뒤 정함, 가안 60자).
- 검증은 코드가 한다: 범위 밖 번호·중복 번호·빈 줄·N 초과는 버린다. 남은 것이 0 이면 실패로 본다.
- 프롬프트 규칙(가안): 시장·금리·환율·실적·정책처럼 **브리핑 독자에게 영향이 큰 것**을 고른다; 같은 사건의 중복 기사는 하나만; **입력에 없는 사실·수치를 쓰지 않는다**; 원문 표현을 그대로 옮기지 않고 새 문장으로 쓴다; 공시는 회사와 무엇을 공시했는지만.

### 4. 자리
- 새 패키지 `summarize/`: `NewsDigest`(선택된 항목 + 줄) 모델, `Summarizer` 프로토콜, Claude 어댑터, 입력 전처리.
- `run()` 이 `collect` → `summarize`(있으면) → `compose` 로 간다. `JobDeps` 에 `summarize: Callable | None` 을 더한다 — 키가 없으면 `None`(수집 소스의 "키 없으면 비활성"과 같은 꼴).
- `compose_simple` 은 `digest` 가 있으면 뉴스 섹션을 `lines`(요약 줄, 출처 표기) + `links`(원문)로, 없으면 v0 처럼 만든다. 렌더러는 바뀌지 않는다.

### 5. 실패
- 키 없음 → 단계 자체가 없음(v0). 호출 실패·타임아웃·`stop_reason=refusal`·스키마 불일치·검증 후 0건 → **경고 로그 + v0 목록**. 작업은 성공으로 끝난다. 섹션 설명에 "자동 요약 없이 최신순" 한 줄을 넣어 독자도 안다.
- SDK 오류는 유형별로 잡는다(`RateLimitError`, `APIStatusError`, `APIConnectionError`, `APITimeoutError`). 비밀값이 로그에 섞이지 않게 예외 메시지를 그대로 찍지 않는다.

### 6. PoC 와 판정
- **Task 1 = PoC.** 실제 하루치 수집 결과(≤80건)를 저장해 두고 같은 입력으로 Opus 5.5(`medium`·`low`)·Sonnet 5.5·Haiku 5.5 를 돌린다. 기록: 선택 건수·줄 길이·토큰(`usage`)·비용·소요 시간, 그리고 아래 기준의 눈검사.
- **판정 기준**(각 줄): ① 입력에 없는 사실·수치 0건 ② 원문 리드의 단순 축약이 아님 ③ 같은 사건 중복 없음 ④ 한국어가 자연스러움 ⑤ 60자 안. 모델 간 차이가 없으면 싼 쪽으로 내린다.
- PoC 결과는 `docs/01_research/2026-10-12_news-summary-poc.md` 에 남기고 N·effort·모델·길이 상한을 거기서 확정한다.

### 7. 비밀값·설정
- `APP_ANTHROPIC_API_KEY: SecretStr | None`, `APP_SUMMARY_MODEL`(기본 `claude-opus-5-5`), `APP_SUMMARY_PICKS`(기본 PoC 뒤 확정, 가안 7), `APP_SUMMARY_TIMEOUT_SECONDS`(120). 프롬프트 문구는 Settings 가 아니라 코드 상수(검색어를 Settings 로 올리지 않은 선례와 같음).
- SDK 는 `ANTHROPIC_API_KEY` 환경변수를 스스로 읽지만, 이 프로젝트는 설정을 `Settings` 로만 읽으므로 **키를 명시적으로 넘긴다**.

## 버린 옵션과 이유
- **흐름 문단(b)·둘 다(c)**: 입력이 제목+100자라 문단은 날조·해석을 부른다. 문장과 기사의 대응이 흐려져 검증이 어렵다. (c) 는 그 위험에 비용만 두 배.
- **OpenAI**: 가격은 비슷하거나 싸지만 한국어 공식 수치를 확인 못 했고, 이 프로젝트에 두 제공자를 둘 이유가 없다.
- **로컬 Ollama**: 노트북이 5분이면 잠들고 사양을 모른다. 외부 전송을 피하는 장점은 사용자가 "현행 전제 유지"로 수용했다.
- **`compose` 안에 LLM 호출**: 작성기가 외부 I/O 를 떠안아 테스트가 무거워진다. 별도 단계가 작성기↔렌더러 계약 설계 의도("LLM 작성기로 바꿀 때 렌더러가 안 바뀌게")와도 맞다.
- **실패 시 섹션 비움·작업 실패**: 시세가 멀쩡한 메일을 막거나 뉴스를 없애는 것보다 지금과 같은 목록을 보내는 쪽이 독자에게 손해가 없다.
- **모델이 URL·제목을 출력**: 날조 가능. 번호 선택으로 구조적으로 막는다.
- **수집 단계에서 연합 머리말 제거**: 수집 모델은 원문 보존. 제거는 LLM 입력 전처리에서.
- **캐싱·배치**: 효과가 없거나(512 토큰·TTL) 작다($3/월).

## 전제 (깨지면 재검토)
- 수신자는 **본인+소수 지인, 무료, 비상업.** 영리화하거나 수신자가 늘면 약관·저작권 판단을 다시 한다(사용자 결정의 조건).
- 언론사 약관의 "AI 학습" 조항을 추론 입력에 적용하지 않는 것으로 **사용자가 판단**했다. 약관이 "입력·생성"을 명시하도록 바뀌면 재검토(출처를 연합으로 좁히기, 제목만 입력 등이 대안).
- 입력은 제목+리드뿐이다. 본문을 가져오는 결정이 생기면 출력 모양(문단)도 다시 볼 수 있다.
- 메일은 한국어 독자를 위한 것이다.
- 하루 2회 호출. 호출이 늘면(예: 재실행) 비용·요율도 다시 본다. Task 10 으로 재실행 시 수집·요약을 건너뛰므로 지금은 안전하다.
