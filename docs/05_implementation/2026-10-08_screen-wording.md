## 왜 이렇게 했나
| 결정 | 대안 | 고른 이유 |
|---|---|---|
| 신고가는 **비율 1 인 종목만** | 이름만 바꾸고 상위 5개를 그대로 | 신고가 종목이 5개보다 적은 날에는 "고가의 98%"인 종목이 "52주 신고가"라는 제목 아래 실린다. 제목이 거짓이 된다. 조건에 맞는 종목이 없으면 섹션이 없다 |
| 설명에 **충족 종목 수**를 적는다 | 상위 5개만 보여 준다 | 어제 국내 신고가는 9개였다. 5개만 보이면 "그 5개가 전부"로 읽힌다 |
| 신고가 줄에서 "고가 대비 100.0%"를 뺐다 | 그대로 둔다 | 모든 줄이 같은 값이다 |
| 거래량 급증은 **상승 마감만** | 상승·하락을 섹션으로 나눈다 / 그대로 둔다 | 사용자가 원한 것은 단기 매매 후보다. -25% 로 끝난 종목이 "조건 충족"에 실리면 기대와 어긋난다. 섹션을 나누면 메일이 4개 더 길어진다. 방향을 가리지 않는 원래 연구(Gervais 외 2001)와는 달라지는 선택이고, 제목에 "(상승 마감)"을 적어 무엇을 걸렀는지 밝혔다 |
| 충족 조건을 **규칙과 분리** (`RuleSpec.meets`) | 점수 함수 안에서 `None` 을 돌려준다 | `high_ratio`·`volume_ratio` 는 여전히 "얼마나"를 재는 순수 함수다. "어디까지를 충족으로 볼지"는 메일의 정책이고 바뀔 수 있다 |
| 한글 이름은 **종목군을 만들 때** 붙여 DB 에 저장 | 메일을 만들 때마다 조회 | 종목군은 한 달에 한 번 만든다. 발송 때의 외부 호출이 16번 늘지 않는다 |
| 한글 이름 출처가 실패하면 영문 이름으로 계속 | 종목군 구성을 실패로 본다 | 표시 이름 때문에 스크리닝이 통째로 빠지면 안 된다 |
| 거래소 목록을 8페이지씩 | 종목마다 조회 | PoC: 8페이지 × 2거래소(16회, 2초)로 503개 중 500개. 종목별 자동완성 조회는 `BRK-B` 를 찾지 못했다 |
