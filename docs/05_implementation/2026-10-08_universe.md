## 왜 이렇게 했나
| 결정 | 대안 | 고른 이유 |
|---|---|---|
| 출처는 **네이버 순위 조회** | FDR `StockListing('KRX')` | PoC 에서 KRX 목록의 가격·시가총액이 전부 비어 왔다. 플랜의 원래 선택이 깨진 자리다 |
| 우선주는 **종목코드 끝자리**로 가린다 | 이름이 "우"로 끝남 | 이름 규칙은 보통주 `성우`·`에코글로우` 를 잘못 잡는다. 테스트로 고정했다 |
| 리츠는 이름이 "리츠"로 **끝나는** 것 | 포함 | 포함으로 보면 `메리츠금융지주` 가 빠진다. PoC 첫 실행에서 실제로 빠졌다 |
| 받은 순위를 **직접 정렬**하고 종목코드로 **중복 제거** | 응답 순서를 믿는다 | 응답이 완전히 정렬돼 있지 않았고, 장중에는 페이지 사이에 순위가 바뀌어 같은 종목이 두 번 나왔다 (PoC 의 349개) |
| 요청한 수보다 적게 오면 **기존 종목군 유지** | 온 만큼으로 교체 | 부분 응답으로 본다. 절반짜리 종목군으로 바꾸면 그날의 스크리닝이 조용히 틀린다 |
| 한 달에 한 번만 다시 만든다 (연·월 비교) | 매일 | 경계의 종목이 날마다 들락거리면 이력에 구멍이 난다. 월만 비교하면 1년 뒤 같은 달에 안 바뀌므로 연도까지 본다 |
| 출처가 실패해도 예외가 밖으로 나가지 않는다 | 올린다 | 수집 쪽 규칙과 같다. 종목군 갱신 실패로 브리핑이 죽지 않는다 |
| S&P 500 은 **전체**를 쓰고 `size` 는 최소 기준 | 상위 N 개로 자른다 | 목록이 알파벳순이다. 자르면 이름이 뒤쪽인 종목이 빠진다. 시가총액 없이는 "상위"를 고를 수 없다 |
| 빠지는 행은 건너뛴다 (가격이 `"-"`) | 전체 실패 | 신규 상장 종목은 첫 체결 전까지 가격이 없다. 한 행 때문에 400행을 버리지 않는다 |

## 막혔던 부분 / 해결 과정
> 💡 블로그 소재: "값을 보지 않고 확인했다고 적은 것".

**증상**
리서치에서 "`StockListing('KRX')` 한 번에 전 종목의 종가·거래량·시가총액이 온다"를 직접 확인(✅)으로 적었다. PoC 에서 시가총액으로 정렬하려는 순간 `ValueError: cannot convert float NaN to integer` 가 났고, "상위 200"이라고 뽑힌 목록이 알파벳순(`BYC우`, `CJ4우`…)이었다.

**가설과 검증**
- 가설: 일부 종목만 값이 없다 → 시장별로 결측 수를 세어 보니 2,872행 **전부** `Close` 가 문자열 `"-"`, `Volume`·`Marcap` 이 NaN. `lateInfoMsgCd` 열이 전부 `ME005`.
- `'KOSPI'`, `'KOSDAQ'`, `'KRX-MARCAP'` 인자도 같았다.

**원인**
리서치 때의 확인이 `len(frame)` 과 `frame.columns` 뿐이었다. 행이 있고 열 이름이 맞으니 값이 있다고 읽었다. KRX 는 로그인 없이는 지연 시세를 주지 않는 것으로 보인다 (FDR 이슈의 "LOGOUT" 응답과 같은 계열).

**해결**
네이버의 시가총액 순위 조회로 바꿨다. 리서치·분석·태스크 문서에 정정을 적었다. 그 뒤로 "직접 확인"은 값 하나를 눈으로 보는 것까지로 한다 — 이 Task 의 수동 확인도 첫 행의 값을 출력했다.

곁가지: S&P 500 목록의 티커. 위키백과가 `BRK.B` 로 쓴다고 보고 점을 하이픈으로 바꾸는 코드를 넣었는데, 실제 목록에는 점이 없는 `BRKB`·`BFB` 가 들어 있었다. 하이픈이 든 종목이 0개인 것을 보고 알았다. 두 종목의 표를 넣었다.
