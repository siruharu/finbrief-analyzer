## 왜 이렇게 했나
| 결정 | 대안 | 고른 이유 |
|---|---|---|
| `DeliveryLog` 는 **호출마다 커밋**한다 | 실행 전체를 한 트랜잭션으로 | 선점은 메일이 나가기 전에 커밋돼 있어야 다른 프로세스가 본다. 한 트랜잭션이면 중간에 죽을 때 "보냈는데 기록이 없다"가 된다 |
| 순서는 선점 → 발송 → 기록 | 발송 → 기록 | 기록을 못 남기는 쪽(pending 으로 남음)이 두 번 보내는 쪽보다 낫다 |
| 치명 오류(`fatal`)가 나면 **남은 수신자를 선점하지 않고** 끝낸다 | 전원 시도 | 인증이 깨졌으면 전원 실패한다. 선점하지 않고 두면 다음 실행에서 그대로 보낼 수 있다 |
| 치명 오류를 낸 그 수신자는 `failed` 로 기록 | pending 으로 둔다 | `failed` 는 다시 선점된다. 앱 비밀번호를 고친 뒤 다시 실행하면 그 사람도 받는다 |
| 재시도 가능 오류는 즉시 1회만 다시 보낸다 | 대기 후 여러 번 | 태스크 설계 그대로다. 그래도 실패하면 `failed` 로 남아 다음 실행이 다시 연다 |
| `mark_sent` 가 DB 오류로 실패해도 `sent` 로 센다 | `failed` 로 센다 | 메일은 실제로 나갔다. 행은 pending 으로 남아 재발송을 막는다. 로그에 남긴다 |
| 발송 불가 브리핑은 `aborted=True` | 정상 종료 | 아무에게도 못 보낸 실행이다. Task 7 이 0 이 아닌 종료 코드로 끝내게 한다 |
| 운영자 알림은 발송 불가일 때만 보낸다 | 치명 오류에도 보낸다 | 알림도 같은 SMTP 경로다. 인증이 깨졌으면 보낼 수 없다 |
| 운영자 주소가 없으면 로그만 남긴다 | 오류 | `operator_email` 은 선택 설정이다 |
| 로그에는 `mask_email` 을 거친 주소만 | 전체 주소 | 공통 규칙. 앞 두 글자와 도메인만 남긴다 |
| 실패 사유로 `str(error)` 를 그대로 저장 | 다시 요약 | Task 5 에서 이 문자열을 예외 클래스 이름과 응답 코드로만 만들게 했다. 서버 문구·비밀값이 섞이지 않는다 |
