## 왜 이렇게 했나
| 결정 | 대안 | 고른 이유 |
|---|---|---|
| `pblntf_ty=B`(주요사항보고) + `corp_cls=Y`(유가증권) 고정 | 필터 없이 전부 | PoC 에서 필터 없이는 하루 449건이고 대부분 펀드 투자설명서였다. 필터를 주면 3건이다 |
| 한 페이지(100건)만 요청 | 페이지 넘기기 | 위 필터로 하루 한 자릿수다. 100건을 넘는 날이 오면 그때 본다 |
| 발행 시각은 접수일 00:00 KST | 조회 시각, 정오 | API 가 날짜만 준다. `NewsItem` 은 시간대 있는 시각이 필수다. 지어낸 시각 중 "그날의 시작"이 가장 덜 속인다 |
| `since` 를 **KST 날짜 단위**로 비교 | 시각 그대로 비교 | 00:00 으로 찍힌 당일 공시가 "09:00 이후" 조건에 전부 걸러진다 |
| 접수번호는 숫자 14자리만 허용 | 받은 값 그대로 링크에 붙이기 | 링크를 접수번호로 조립한다. 외부 값이 URL 에 그대로 들어가므로 형식을 확인한다 |
| `013`(결과 없음)은 빈 목록, 그 밖의 코드는 `CollectError` | 전부 예외 | 공시 없는 날(주말)은 실패가 아니다 |
| 오류에 서버의 `message` 를 싣되 키와 같은 문자열은 가린다 | 코드만 싣기 | 설계 메모가 "코드와 메시지"를 요구한다. DART 문구에 키가 들어온 적은 없지만 서버가 입력을 되받아 적는 경우를 막아 둔다 |
| 키를 `hide_from_http_log` 에 등록 | — | Task 8 에서 찾은 문제. 키가 쿼리 파라미터다 |
| 최신 접수번호 순 | 응답 순서 | 발행 시각이 전부 같은 값이라 시각으로는 정렬되지 않는다. 접수번호가 접수 순서다 |
